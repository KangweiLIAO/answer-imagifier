# 测试维护

## 运行

```sh
npm test
```

该命令先构建扩展，再运行所有 `*.test.mjs`。`build.test.mjs` 和 `csp.test.mjs` 会读取真实构建产物。

修改单个模块时可先运行相关测试：

```sh
node --test tests/form-controls.test.mjs tests/export-pipeline.test.mjs
```

提交前仍需运行 `npm test`。这里使用 Node 内置测试运行器；不新增测试框架。

## 测试层次

| 类型 | 示例 | 验证范围 |
| --- | --- | --- |
| 规则与适配器 | `settings`、`layout`、`checklist`、`form-controls` | 边界值、实时状态、去重及各模块的职责 |
| 导出集成 | `export-pipeline` | 调用真实 `createCard()`，经过快照、适配、清理、组装和布局 |
| 界面行为 | `panel-settings`、`dom` | 加载真实面板／入口模块，操作 DOM，验证手动渲染、过期结果和回答识别 |
| 构建边界 | `build`、`csp` | 扩展匹配域名、权限及 CSP 兼容性 |
| 浏览器视觉验证 | `samples/intelligent-ui/` 与实际 PNG | 字体、图表、真实排版、主题和栅格化结果 |

不能用测试数量或 DOM 断言代替实际图片验收。新增组件时先确定需要保护的行为，再选择对应层次；无需在每层重复同一组断言。

## 公共工具

- `helpers/dom.mjs`：创建 DOM、读取 fixture、建立副本与源节点映射、读取测试内联样式，以及在测试结束后恢复属性。
- `helpers/browser.mjs`：补足 LinkeDOM 缺少的 dialog、图片解码和 Canvas 方法；方法均通过测试结束钩子恢复。
- `helpers/module.mjs`：使用现有 esbuild 加载真实模块和资源，再在独立 VM 中执行。通过模块路径明确指定替代依赖，无需用正则改写源码。

`cloneForAdapter()` 只准备适配器的输入，不排列导出阶段，也不模拟生产清理逻辑。若要验证多个阶段的顺序或最终内容，使用真实生产入口。

修改 `globalThis`、DOM 原型或其他共享对象时使用 `stubProperties(t, target, values)`。它保存并恢复原属性描述符；原本不存在的属性会被删除。使用共享全局／原型替代的测试不要在同一进程内并发运行。

## 替代依赖的边界

导出集成测试仅替代浏览器资源准备和图片输出依赖。真实内容转换、长图组装和布局编排继续执行。资源准备替代函数还会检查长图已挂载，并验证协调器实际调用了它。

面板测试替代存储、重型图片生成、计时器和部分本地化文案，保留真实回答识别、设置校验和 DOM 操作。每次加载使用独立模块状态，避免面板 `active` 等状态跨测试残留。

LinkeDOM 没有真实布局引擎；测试里的 Canvas 文字测量及内联样式读取只是可控替代。这些测试不能证明像素宽度、图片解码或 PNG 内容正确。相关行为仍需在浏览器中验证。

## 新增或调整测试

1. 使用最小 HTML 表达触发条件；复杂真实样本放进 `fixtures/`，使用 `readFixture()` 读取。
2. 断言用户可见内容、当前状态或明确的导出标记，避免检查源码排版和压缩后的变量名。
3. 适配器测试不手写按钮清理流程；清理归属、模块间相互影响由导出集成测试覆盖。
4. 保留已有故障的回归场景，如表单／清单去重、0% 进度、实体文字、原生 Mermaid 和过期预览禁用导出。
5. 删除测试前确认其行为已由其他测试覆盖。将用例按职责归档，避免恢复一个混合所有主题的 `core` 文件。
